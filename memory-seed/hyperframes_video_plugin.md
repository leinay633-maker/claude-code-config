# HyperFrames 渲染与画面检查易错点

加载、插件目录和命令入口按 `make-video/SKILL.md` 执行。以下只补充渲染排查细节。

## 预览成功不代表成片正确

- 正式渲染先检查首段日志与解码帧。时间线未注册或 readiness 超时可能让预览正常、成片只剩背景。
- `window.__timelines[id]` 的键须与 composition 标识一致，构建完成后注册有效时间线；不要把异步函数的返回值误解构成 `undefined` 再覆盖注册项。
- 长片内存持续增长时，先测短段和少量并发。分段、回收和续跑参数只采用当前安装版本明确支持的写法，不照搬旧环境变量。
- 稀疏关键帧警告先和实际解码画面对照；未发现冻结时，不仅为消除警告就重编码全部素材。

## 布局检查

- `data-layout-allow-occlusion` 用于确实有意叠放、且已目视确认可读的文字元素；嵌套文字单独核对，不能假定从面板继承。
- 画布被检查器当成遮挡物时，先检查真实层级和文字可读性，不用豁免掩盖遮挡。
- 文字行盒超出裁切容器可能导致对比度采样错误。盒子应贴合实际文字；适合内容宽度的场景可用 `width: max-content`，但仍要检查真实越界。
- 尚未出场且不应参与布局检查的内容按当前检查器规则处理，不能只凭透明度认为它不会被采样。

## 性能与音频

- 预览卡顿与逐帧渲染分开诊断。循环里反复设置 `blur()` 或 `shadowBlur` 时，考虑离屏缓存，再比较单帧耗时。
- 不要每帧用 `getImageData` 做画布测速；读回像素可能改变加速路径，使测得的成本偏离实际渲染。
- 自动化等待要返回布尔就绪状态，不直接返回带 `then()` 的动画对象。
- 大面积逐帧变化的颗粒可能显著增加码率；先模拟目标压缩，再决定是否修改画面或另出编码版本。
- 解析响度测量输出时保留 `nan` 和 `-inf` 的静音帧位置，不因只匹配数字而让后续时间错位。
- 无头渲染缺少某种图形能力时，核对实际后端再选实现，不把一台机器的结果当成普遍限制。
