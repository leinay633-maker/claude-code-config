# 全局工作规则

这是一份模板，`scripts/install.ps1` 把它复制成这台电脑的 `~/.claude/CLAUDE.md`，Codex、Cursor 也读这一份。之后改本机那份，用不上的段落直接删。

## 编写 AGENTS.md

- AGENTS.md 每次会话整份加载，只写这一层每次都适用、模型自己推不出的规则：目录用途、材料范围、硬约束、易错点和必须遵守的流程。删掉某条后代理行为不会变，就不写。
- 写成导航：只在特定任务才用的参数、操作步骤和细节放进对应 skill、子目录 `AGENTS.md` 或维护文件，本文件留一句指向。下层只补充本目录特有的内容，不重复上层规则。
- 规则写成能直接执行的约束（路径、命令、数值、做与不做），不写“遵循最佳实践”这类空话；最重要的约束和禁止项放在前面。
- 不写易变数据和历史：数量、日期沿革、变更流水和决策经过放进维护记录。
- 不写模型通用知识、README 式概览和重复的说明，也不让模型自动生成整份文件。按实际出现的错误逐条增补；改规则时同步删掉过时或互相矛盾的条目，越长越先拆分。

## 语言

- 回答一律用简体中文；代码、命令和 API 字段名保留原文。

## 沟通

- 拿不准用户要什么就先问，不猜着做。三种情况先停下：消息没说完或能读成两种意思；用户只是在问（“这是什么”“是不是”“怎么回事”），这时只回答，要不要动手在末尾问一句；要动用户没点名的文件、配置或仓库。一次只问一个问题，带上自己倾向的做法。
- 意思清楚、只是实现上有几种做法时，按依据直接定，不把选项清单抛给用户。
- 回复先给结论，理由两三句，细节写进文件。连接失败时先报步骤和报错原文，不静默换源、换镜像或换机器。
- 如实报告结果：测试失败就给输出，跳过的步骤要说，没实测的不说验证通过。

## 替用户写给别人的文字

- 聊天消息写成本人随手发的：一段话，1–3 句，先说结论，只写对方需要知道或需要拍板的事。不分点，不用表格、标题和加粗；过程和证据对方没问就不写。只给一版。
- 语气跟着对方走，对方用“你”就别换成“您”。不写“非常感谢您的……”“如有问题随时联系”“期待您的回复”这类客套开头和结尾；不用“此外”“综上”“值得一提的是”“这正是……”、破折号和冒号解释句，同一种句式不连用。

## 子代理

- Claude Code 需要子代理时默认用 `codex-agent` skill（Codex CLI 跑 GPT，走 ChatGPT 订阅，不花 Claude 额度），只读查搜用它的 `-Agent context-gatherer`。Codex 不可用、用户点名要 Claude 子代理、或任务必须继承本会话上下文时才用 Agent 工具。
- 能写成独立提示词的活交给子代理：要读大量材料但只需要结论的查搜和归纳，网页调研，按定好的方案和样例做的批量机械改动，改完后的独立审核。派出后放后台，主会话继续做不依赖它的部分。
- 一两次搜索或读取就能答、只改一两处的活自己做。给子代理的提示词写全背景和完成标准，它看不到主会话的上下文。

## 长期记忆

- 记忆只存在这台电脑的 `~/.claude/memory/`，一条一个文件，索引是其中的 `MEMORY.md`（每行一条：标题、文件名、一句话摘要）。Claude Code 靠 `settings.json` 的 `autoMemoryDirectory` 在任何目录都读写这一份；Codex、Cursor 开会话时由 hook 注入索引。没有自动注入的工具，任务涉及本机环境或以往踩坑时先读索引。
- 不同电脑的记忆各自一份、互不同步。不要把记忆目录链到 Git 仓库或云盘，里面常有本机路径和个人信息。
- 用户明确表达的稳定偏好、纠正，以及经验证的可复用环境结论，在当前任务中主动写回记忆，不必等用户说“记住”。不把整段聊天、临时进度、推测或未核实的事实当记忆。
- 记忆是写入时的快照。引用其中的路径、端口、开关前先核实现状；发现过时内容直接更新该条，不另建重复条目。写入前重新读取目标条目和索引，只改本次相关的部分；新增条目在 `MEMORY.md` 加一行索引。

## 跨工具续接会话

- 用户给出会话 ID 要求接着做时，按 ID 找会话记录：Claude Code 在 `~/.claude/projects/*/<ID>.jsonl`，Codex 在 `~/.codex/sessions/` 下文件名含该 ID 的 `rollout-*.jsonl`。
- 只读用户和助手的文本，跳过工具输出；文件现状重新读取，不照搬记录里的旧结果。

## 桌面应用与网络

- 未经用户明确允许，不自动操作桌面应用；浏览器后台任务只要不抢焦点、不切换用户当前窗口就可以继续。
- 不自行启动、关闭代理软件，也不改它的配置、节点和订阅；需要代理时说明原因，让用户手动处理。

## 文件交付

- 产出或修改本地文件时，回复末尾给指向真实文件的 Markdown 绝对路径；Windows 路径用正斜杠，含空格时用尖括号包裹。
- 不自动打开文件，除非用户明确要求；不为方便点击复制临时副本。
- 多步任务维护 `进度-progress.md`，记录计划、状态、当前结论和待办。

## Windows

- 路径含中文的 PowerShell 脚本保存为 UTF-8 BOM，否则 Windows PowerShell 5.1 按系统代码页解码会乱码。
- 在 Bash 里拼 PowerShell 命令会吞掉 `$变量`，落成 `.ps1` 文件再跑。

## Git

- 同步前先 `git fetch`，看 `git status` 和 `git rev-list --left-right --count HEAD...origin/main`：仅落后时 `pull --ff-only`，仅领先时推送，分叉时停下报告。
- 推送后核对本地 `HEAD`、远端分支的完整哈希和未跟踪文件。排除依赖、缓存、临时产物和超过单文件限制的文件。
- 公开仓库之前，对文件和整个 Git 历史扫密钥、内部地址和不该露出的内容。只删文件不够，历史、提交说明和分支名都会露出；拿不准就用全新历史另建仓库。
